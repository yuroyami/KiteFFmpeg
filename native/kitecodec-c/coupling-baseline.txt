# The post-S1.a.8 Kotlin to FFmpeg coupling baseline of kiteffmpeg-core.
#
# The opaque migration changes what the two ratchets mean. Before S1.a.8, direct FFmpeg imports
# stood at 246 and ffmpeg_typed_crossings combined 273 ffkmp_ mentions with 14 direct libav calls
# for 287 total. The reduced cinterop now exposes only KiteFFmpeg-owned declarations, so the durable
# boundary is stricter and simpler:
#
#   cinterop_import_lines counts imports from ffmpeg whose symbol does not begin ffkmp_, kc_ or
#   KC_. These are direct FFmpeg imports, and the ceiling is zero.
#
#   ffmpeg_typed_crossings counts direct libav calls only. Helper traffic no longer belongs in
#   this number because ffkmp_ is the intended opaque boundary, and the ceiling is zero.
#
# ffkmp_call_sites remains reported-only and is deliberately not recorded here;
# direct_libav_call_sites is also reported. Raw FFmpeg struct names are derived from the C
# declarations and forbidden outright, so there are no allowed_struct_type lines.
#
# Matching happens after the context-stack Kotlin lexer strips line comments, KDoc and nested block
# comments, including comments inside ordinary and raw ${...} template expressions. Quoted content,
# nested templates, chars and backtick identifiers remain in their correct lexical contexts.
#
# These numbers are ceilings, never targets. Lowering one is a normal commit. Raising one requires
# the old and new value, the reason and the exact source sites in KPKMP.md's Execution log, following
# section 9's ratchet move table.

cinterop_import_lines 0
ffmpeg_typed_crossings 0
